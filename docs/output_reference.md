# Output files, JSON schemas, and audit reference

This reference describes the current repository's writers and readers. It covers
application-defined fields completely; raw OpenAI response objects are preserved
SDK/provider data and can contain additional, version-dependent fields. An older
project may omit newer fields. `schema_version` in the manifest is the extraction
schema/cache version, **not** a version for every file described here.

## Finding the right file

| Question | File or location |
|---|---|
| What settings were used? Was extraction completed? | `manifest.json`; raw response status for CLI runs |
| What image did the request use? | `processed_api_image.*`, or `segments/segment_*.png` |
| What instructions and columns were requested? | `prompt.txt`, `profile.yml`, `schema.json` |
| What table did the model produce? | `extracted.json` and `extracted.csv`; raw attempts for exact response provenance |
| What is the saved reviewed table? | `corrected.json` and `corrected.csv` |
| Why was a value changed? | `feedback.jsonl`, `notes.md` |
| What happened before interruption? | `extraction_session.json`, `raw_response.json` |
| Where did a continued project come from? | `manifest.json.parent_run_id` names its sibling source folder |
| Where are unsaved GUI edits? | Local recovery folder, not the run directory |

All application JSON, JSONL, YAML snapshots, prompt text, notes, and CSV are written
as UTF-8. JSON uses readable Unicode, two-space indentation, and a trailing newline;
JSONL has one JSON object per line. `null` means no value is available, not zero.
An empty list means no entries are saved. Empty table cells use `""`, not `null`.
Use the explicit `fields` array for column order, rather than relying on a JSON
reader's object-key ordering. Timestamps generated by the application are UTC
ISO 8601 strings; folder names use `YYYYMMDDTHHMMSSZ`, with collision suffixes.

## Lifecycle and authority

| Artifact | Dry run | Ordinary CLI run | GUI recoverable run | Review/continuation |
|---|---|---|---|---|
| Source/prepared images, profile, prompt, schema | Yes | Yes | Yes | Retained/copied |
| `manifest.json` | Yes | On successful job export | Updated from checkpoint | Continuation updates derived metadata |
| `notes.md`, `feedback.jsonl` | Heading/empty file | Heading/empty file | Heading/empty file | Save replaces contents with current review records |
| `raw_response.json` | No | Single response or segment envelope | Attempts and pending response | Continued attempts retained |
| `extracted.json`, `extracted.csv` | No | On successful export | Includes partial or zero-row tables | Regenerated from checkpoint |
| `extraction_session.json` | No | No | Yes | Copied and extended by continuation |
| `corrected.json`, `corrected.csv` | No | No initially | No initially | Save Project or continuation creates them |
| `segments/` | No | If segmented | If segmented | Copied by continuation |

These are normal outcomes, not transactional guarantees. A failure during image
preparation, validation, or disk writing can leave an incomplete folder. A CLI
validation error preserves its raw response before raising and may leave no
manifest or table. A dry-run folder cannot be loaded as a review table because
it has no extracted/corrected JSON.

In a recoverable run, `extraction_session.json` is authoritative for extraction
progress. Loading a project calls export repair: it can rewrite `extracted.*`,
`raw_response.json`, and `manifest.json`. Hand edits to those derived files can
therefore disappear. Checkpoint-owned corrected exports carry `session_row_count`;
manual review saves omit that marker and repair leaves them alone. Do not remove
or edit checkpoint inputs to try to change a continuation.

Load Project reads JSON, not CSV. It prefers corrected JSON if present; malformed
corrected JSON raises an error rather than silently falling back. CSV-only edits
do not change the loaded table. Copy the whole folder to move a project: current
paths are relative to it; older absolute paths are rebased to local copies, never
followed to unrelated external folders. Escaping paths are rejected. Missing
images can prevent preview even if table data loads.

## Extraction tables and CSV

Illustrative `extracted.json` for a two-field profile (real names come from the
selected profile):

```json
{
  "fields": ["Unit", "Description"],
  "rows": [{"Unit": "Qa", "Description": "Alluvium."}],
  "notes": [],
  "warnings": [],
  "extraction_status": "complete"
}
```

| Key | Type | Meaning and presence |
|---|---|---|
| `fields` | string array | Required; exact profile column names and order. |
| `rows` | object array | Required; source-order records with one string per profile field. Zero rows is allowed. Headings, introductions, and footnotes can be rows when the profile requests them. |
| `notes` | string array | Model extraction decisions/ambiguities. GUI sessions accumulate validated response notes; partial recovery may have none. Ordinary CLI aggregation currently exports an empty list. |
| `warnings` | string array | GUI model/session warnings plus an incomplete warning when applicable. Ordinary CLI aggregation currently carries token-limit warnings, not all model warnings. Consult raw responses for omitted notes/warnings. |
| `extraction_status` | string | Added by GUI checkpoint export; absent from ordinary CLI extraction JSON. See status dictionary below. |

Manual `corrected.json` always has `fields` and `rows`. When the project has an
extraction status, it also has `extraction_status` and `warnings` (empty for
`complete`, otherwise `INCOMPLETE extraction: partial table.`). It does not copy
model notes or all original warnings; retain extracted/raw files. Review status
and comments live in feedback, not extra table columns. Corrections are not
revalidated against the profile's controlled vocabulary on Save Project.

Continuation-generated corrected JSON initially has the extraction envelope
above plus `session_row_count` (integer count of accumulated machine rows). This
internal marker lets repair append new rows without duplicating previously
exported rows. It is not the corrected table's row count after reviewer insertions
or deletions. A manual save replaces this envelope with the manual format.

Both CSV files have a header in `fields` order, one record per row, and standard
CSV quoting for commas, quotes, and embedded newlines. They have no notes,
warnings, completion flag, or review status. UTF-8 is written without a BOM;
select UTF-8 and text columns when importing into a spreadsheet to preserve
symbols and leading zeros. A physical text line is not necessarily a CSV record.

## Request schema and validation

`schema.json` is the initial **model-output JSON Schema**, not a schema for
manifest, checkpoint, corrected JSON, or raw response envelopes. Its components:

| JSON Schema keyword/path | Meaning |
|---|---|
| `type: "object"` | Response must be an object. |
| `additionalProperties: false` | Extra top-level keys are prohibited. |
| `required` | `fields`, `rows`, `notes`, `warnings` must all be present. |
| `properties.fields` | Array of strings; item `enum` lists profile fields. Local validation additionally enforces exact order and equality. |
| `properties.rows.items` | Object, no extra properties, every profile field required. |
| `properties.rows.items.properties.<field>` | String with a generated or profile-supplied `description`; optional `enum` for closed vocabularies. |
| `properties.notes`, `properties.warnings` | Arrays of strings with descriptive guidance. Empty arrays are valid. |

The request wraps this schema in `text.format` with `type: "json_schema"`,
`name: "<profile_id>_extraction"`, a profile-based `description`, `strict: true`,
and `schema`. That wrapper is not in `schema.json`. Continuation adds required
integer `resume_after` constrained to the current segment's saved row count;
the initial saved schema does not include it. The runner checks and removes
this boundary field before validating table data.

Local Pydantic validation rejects missing/extra row fields and extra envelope
keys, checks string values and exact `fields` order, and enforces allowed values.
If a vocabulary contains double quotes, the generator omits its API enum to
avoid a strict-schema restriction; the prompt and local validator still enforce
the complete vocabulary. A blank value must be allowed by an enum to pass it.
Structural validity does not prove transcription accuracy, geological correctness,
complete coverage, or valid GeMS relationships. See [GeMS review](gems_dmu_review.md).

| `prompt_hash` | string | Hash of rendered initial prompt text. |
| `schema_hash` | string | Hash of canonically serialized initial response schema. |

| `request_fingerprint` | string | Initial full-image request identity; see hash details below. |

| `image_detail` | string | Selected image detail (`high`, `low`, `auto`, or `original`); actual support depends on model. |
| `max_output_tokens` | integer or null | Per-request output allowance; null omits the explicit limit. It is not a run-wide budget. |
| `api_call_mode` | string | `dry_run`, `fresh_api_call`, `cache_reuse`, `mixed`, or `continuation`. |
| `segmented_mode` | boolean | Whether crop extraction was requested. |

| `segment_calls` | object array | CLI per-segment summaries (below). GUI sessions leave this empty and record `attempts` instead. |
| `input_tokens` | integer or null | Reported input token count, including cached input. |
| `output_tokens` | integer or null | Reported output token count, including reasoning tokens when supplied by API. |

| `cached_tokens` | integer or null | API-side cached input subset, not local request-cache hits. |
| `reasoning_tokens` | integer or null | Output reasoning subset; not additional to output tokens and not reasoning text. |
| `elapsed_seconds` | number | CLI job wall time including preparation; GUI accumulated session execution time, inherited by continuation. Not human review time. |
| `estimated_cost_usd` | number or null | Local catalog estimate; null when model/tier or required usage is unavailable. Not an invoice. |
| `warnings` | string array | Run warnings; see GUI/CLI differences above. |
| `rough_image_tokens_estimate` | integer | Preview heuristic for the full prepared image, not an API usage count or sum of crop usage. |
| `image_preparation` | object | Boolean `was_converted` and `was_resized`; conversion also means re-encoding due to resize. |
| `output_paths` | object | File-role keys mapped to run-relative paths; see below. Includes planned, not necessarily existing, files. |
| `package_version` | string | Application package version, not a Git revision or dependency lock. |
| `extraction_status` | string, GUI only | Checkpoint status. |
| `continuation_available` | boolean, GUI only | Status is not `complete`; this does not guarantee a successful continuation. |
| `parent_run_id` | string, continuation only | Immediate source folder name. |

`output_paths` keys are `source_image`, `processed_image`, `profile`, `prompt`,
`schema`, `raw_response`, `extracted_csv`, `extracted_json`, `corrected_csv`,
`corrected_json`, `manifest`, `notes`, and `feedback`. They map to the filenames
in the [README inventory](../README.md#run-folders-and-audit-trail).
The checkpoint and segment directory are not separate entries in this mapping.

Each CLI `segment_calls` entry has `segment_index` (one-based integer),
`segment_path` (relative string), `request_fingerprint` (string), `api_call_mode`
(`fresh_api_call` or `cache_reuse`), `usage` (object containing the five nullable
token fields above), and `token_limit_warning` (string or null). Even whole-image
CLI extraction has one such entry with the prepared image as segment 1.

GUI usage sums known counts from non-cache attempts, including inherited parent
attempts and validation failures with usage. Pending responses are not included
until recorded as attempts. All-local-cache GUI usage can be null. CLI totals
include usage stored in reused cache entries; zero totals are converted to null.
Thus neither a nonzero CLI cache estimate nor a continuation total should be
read as the additional charge of that operation.

The cost calculation subtracts cached tokens from input tokens, applies catalog
rates per million to uncached input, output, and cached input (when a cached rate
exists), applies the tier multiplier, and rounds to eight decimals. Checkpoint
repair recomputes this with the installed catalog; historical estimates can
change when reopening under a different catalog. Rates are not frozen in runs.

## Hashes and request fingerprints

Image hashes digest file bytes. `prompt_hash` digests UTF-8 rendered prompt text.
`schema_hash` digests `json.dumps(schema, ensure_ascii=False, sort_keys=True)`
encoded as UTF-8, using default separators. It is not a hash of the pretty-printed
`schema.json` file, so a file-hash command will give a different answer.

`request_fingerprint` uses that same sorted-key JSON serialization on an object
with keys `processed_image_hash`, `profile_id`, `profile_fields`, `prompt_hash`,
`model`, `reasoning_effort`, `service_tier`, `image_detail`, `max_output_tokens`,
and `schema_version`. For fingerprinting, schema version is expanded to
`1.0|seg:<0-or-1>|h:<height>|o:<overlap>`; the manifest stores only `1.0`.
Segment fingerprints substitute the crop hash. The run fingerprint uses the
full prepared image even for segmented mode. Segment settings affect the
fingerprint even when segmentation is disabled.

The fingerprint does not directly contain `schema_hash`, profile file bytes,
package version, or a pricing snapshot. It is a cache identity, not a comprehensive
proof of identical software. Continuation retains the original fingerprint and
initial prompt/schema hashes even when changing the token allowance and sending
continuation instructions. Inspect attempts and parentage for that history.

Checkpoint `artifact_hashes` instead hash actual saved file bytes for
`profile.yml`, `prompt.txt`, `schema.json`, and every listed segment/input image.
Continuation verifies those entries and rejects changed files. Ordinary loading
checks paths but does not verify these hashes. Hashes are not digital signatures.

## Raw responses and attempts

There are three formats for `raw_response.json`:

| Run path | Top-level shape |
|---|---|
| Ordinary CLI, one response | Raw SDK response object itself |
| Ordinary CLI, multiple crops | `{"segmented": true, "segments": [<raw response>, ...]}` in crop order |
| GUI recoverable session | `{"attempts": [<attempt>, ...], "pending": <raw response or null>}` |

In the GUI envelope, each normal attempt contains:

| Key | Type | Meaning |
|---|---|---|
| `raw_response` | object | Preserved response, including usage/status when present. |
| `segment_index` | integer | **Zero-based** index into checkpoint `segments`, unlike CLI segment summaries. |
| `resume_after` | integer or null | Count of saved rows in this segment before continuation; null for initial request. |
| `prompt` | string | Actual request prompt, including continuation instructions and saved prefix. |
| `cache_reused` | boolean | Local cache reuse; these attempts do not add GUI usage totals. |
| `error` | string, error attempts only | Validation failure text. Such entries have raw response, segment index, and boundary but omit `prompt` and `cache_reused`. |

`pending` is the latest response snapshot received while work is unresolved. Its
`id` allows retrieval of a known background response after interruption. It is
cleared when an attempt is recorded. This is not a log of every polling response,
network retry, or HTTP exchange.

Raw objects are serialized by the SDK's `model_dump(mode="json")`; the application
does not define a closed schema for them. The fields it consumes are:

- `id`: response identifier used for retrieve/cancel.
- `status`: terminal or background status, such as `queued`, `in_progress`,
  `completed`, `incomplete`, `cancelled`, or `failed`.
- `incomplete_details.reason`: token-limit or other interruption reason;
  `max_tokens` is also recognized as a token-limit reason.
- `error`: provider error details, copied into warnings when present on interruption.
- `usage.input_tokens`, `usage.output_tokens`, `usage.total_tokens`,
  `usage.input_tokens_details.cached_tokens`, and
  `usage.output_tokens_details.reasoning_tokens`: source of usage summaries.
- `output[]`: for partial recovery, only items with `type: "message"` and their
  `content[]` parts with `type: "output_text"` contribute `text`. That text is
  JSON serialized inside a string, requiring a second parse for the table.

The SDK's `output_text` convenience attribute is used during normal parsing and
need not appear as a saved top-level key. Other provider metadata, output item
types, refusals, and reasoning metadata are retained as returned. Do not assume
all these fields exist, or treat arbitrary content parts as table text. A local
cancellation before submission can produce only `{"status": "cancelled"}`.

## Extraction checkpoint and continuation

`extraction_session.json` is a versioned application object. Unknown top-level
keys are rejected. Current fields and defaults:

| Key | Type/default | Meaning |
|---|---|---|
| `version` | integer `1` | Checkpoint format, distinct from manifest schema version. |
| `manifest` | object | Base manifest, not necessarily the latest derived status/usage totals. |
| `segments` | string array | Ordered relative image paths; whole-image run has one prepared image. |
| `segment_fingerprints` | string array, `[]` | Initial per-image cache identities aligned with `segments`. |
| `use_cache` | boolean, false | Cache use/store policy for this session. |
| `allow_cache_lookup` | boolean, true | False for a forced rerun. |
| `artifact_hashes` | object, `{}` | Relative path to file-byte SHA-256 mapping. |
| `segment_index` | integer, `0` | Current zero-based segment; equals segment count when all complete. |
| `rows` | row array, `[]` | Accepted machine rows accumulated across segments and attempts. |
| `segment_rows` | row array, `[]` | Current segment's saved prefix; reset on moving to next segment. |
| `attempts` | object array, `[]` | Completed/failed validation attempts described above. |
| `pending` | object or null | Latest unresolved raw response snapshot. |
| `pending_resume_after` | integer or null | Boundary used by the pending request. |
| `status` | string, `ready` | Session status; not restricted to a fixed enum. |
| `warnings`, `notes` | string arrays, `[]` | Accumulated session messages. Export adds an incomplete warning separately. |
| `review_rows` | row array or null | Review table inherited when continuing. |
| `review_originals` | row array or null | Review-aligned comparison baseline inherited when continuing. |
| `review_base_count` | integer, `0` | Machine row count before continuation, used to append only new machine rows to review exports. |

| Status | Interpretation |
|---|---|
| `ready` | Initialized or between segments. |
| `running` | Request underway; may remain after a crash. |
| `complete` | All segments processed; still requires human review. |
| `max_output_tokens` | Output allowance exhausted; saved rows may be only a prefix. |
| `cancelled` | Cancellation recorded; may have partial rows. |
| `interrupted` | Exception prevented normal completion; inspect warnings and pending ID. |
| `validation_error` | Response failed structural/field validation; raw response retained. |
| `boundary_review` | Continuation boundary could not be safely accepted, including repeated saved rows. Inspect the join and raw output. |
| `failed`, `incomplete`, other provider reason | Propagated API interruption. Treat any value except `complete` as incomplete. |

Partial recovery keeps only the contiguous prefix of complete, locally validated
row objects after a matching `fields` array. It stops at a bad/truncated row;
it does not repair text or skip ahead. Continuation resends the same segment image
with the saved machine prefix. Its boundary count is per segment, not the total
project row count or a reviewer-edited row count. A repeated suffix/prefix match
causes new rows to be withheld for review rather than deduplicated automatically.
Rows from overlapping image crops are otherwise concatenated without automatic
deduplication or global hierarchy reconciliation.

Continue Extraction copies the source folder to a new sibling, disables local
cache use, updates `parent_run_id`, `run_id`, token allowance, and call mode,
and preserves the review baseline. It retains inherited attempts, creation time,
and elapsed time. A pending ID is retrieved first; changing the allowance cannot
change an already submitted request. New requests use the new allowance. Review
changes are not substituted for machine rows in continuation prompts. In a
continued project's extracted export, the prefix can be the review-aligned
`review_originals`; use checkpoint machine rows and raw attempts when exact
original response provenance is needed.

Checkpoint and derived session JSON writes use a temporary file, flush/fsync,
and replacement. CSV and manual review saves are not a single atomic transaction
across files. A crash can leave files at different revisions; repair and recovery
reduce that risk but do not make the folder an immutable database.

## Review feedback and notes

`notes.md` is reviewer-authored run-level Markdown, initially `# Review notes`.
It is independent of the model's `notes` array and of optional profile notes
that were included in the prompt.

`feedback.jsonl` is JSON Lines, **not** a JSON array. Blank initial content is
normal. Save Project writes retained in-memory events plus one `final_review`
record per current row/field and a `note` record for nonempty notes text.
It rewrites the file; it is not an append-only, tamper-proof event log. Reopened
histories can contain repeated final-review records. Read records in file order;
malformed lines and non-object values are skipped by the current loader.

| Key | Type | Meaning |
|---|---|---|
| `timestamp` | string | UTC event/save time. |
| `event_type` | string | Event category below. |
| `run_id` | string | Project identifier when the event was recorded; inherited records may name parent runs. |
| `profile_id` | string | Active profile ID. |
| `image` | string | Active image filename label, not a content hash or stable source ID. |
| `row_index` | integer or null | Zero-based row position at event time; null for run notes. |
| `field` | string | Profile column, `__row__` for row operations, or `notes` for run notes. |
| `model_value` | string | Comparison baseline, or operation-specific source value. |
| `corrected_value` | string | Saved value or operation result. |
| `field_name` | string | Backward-compatible alias of `field`. |
| `original_value` | string | Backward-compatible alias of `model_value`. |
| `status` | string | Review assessment; see below. |
| `comment` | string | Reviewer explanation or generated operation description. |

All values in the two value fields are stringified (`None` becomes `""`). Row
operations can therefore contain Python-style dictionary representations rather
than nested JSON objects; do not parse those strings as guaranteed JSON.

| `event_type` | Payload interpretation |
|---|---|
| `cell_edit` | Edited cell compared with its original baseline. |
| `row_metadata` | `field: "__row__"`; previous and new row status in value fields, with the current row comment. Also emitted for comment-only changes. |
| `row_added` | `field: "__row__"`, empty baseline, corrected value `added`. |
| `row_duplicated` | Source and duplicated row string representations. |
| `row_deleted` | Removed row string, corrected value `deleted`. |
| `row_reordered` | Old and new zero-based positions as strings; `row_index` is target position. |
| `final_review` | Save-time assessment for each cell, including unchanged cells. |
| `note` | Run notes text in corrected value, `row_index: null`. |
| `cell_feedback` | Generic record-builder default; older/integration records may use it. |

GUI row statuses are `accepted`, `needs_review`, and `bad_extraction`. Saving an
accepted row with a changed cell derives `accepted_with_minor_edit` for that
cell. `note` is used for notes; the generic record builder defaults to `corrected`.
These labels are reviewer assessments, not numerical confidence probabilities.
Cell-edit events can record an edit assessment before the whole row is approved.
On reload, the GUI processes feedback in file order to restore row statuses and
nonempty comments at each recorded index; `accepted_with_minor_edit` maps back
to row status `accepted`. An empty later comment does not clear an earlier
nonempty comment during this reconstruction.

Row indices are positional, not persistent identifiers. Insertions, deletions,
and reordering change their meaning. During editing the GUI moves baseline rows
with review rows; on ordinary reload it reconstructs baseline rows positionally
from extracted JSON, padding/truncating to the corrected row count. Consequently
`model_value` after structural edits/reload is not always an exact match to the
same original source entity. Retain raw outputs and review row-operation events
when auditing structural changes; feedback is not a reliable event-sourcing format.

## Profile, prompt, and image artifacts

`profile.yml` is normally a copy of the selected YAML. If any field uses an
external vocabulary, a resolved snapshot is written: `enum` contains allowed
values (including blank), `vocabulary` becomes null, and `terms` retains
term-to-definition mappings. The run then has no external vocabulary CSV dependency.

| Profile key | Type/meaning |
|---|---|
| `id`, `name`, `task_label` | Nonempty strings: identifier, display name, prompt task label. |
| `fields` | Nonempty ordered list of unique, nonblank column strings. |
| `include_intro_footnotes` | Boolean instruction to include standalone descriptive rows. |
| `preserve_wording` | Boolean preservation instruction. |
| `normalize_line_breaks` | Boolean paragraph-joining instruction. |
| `normalize_hyphenated_line_breaks` | Boolean line-wrap hyphenation instruction. |
| `special_instructions` | String list; an input string is normalized to a one-item list, null to empty. |
| `field_rules` | Mapping from existing field names to rule objects. |
| `allow_segmented_mode` | Boolean, default true; false blocks segmented extraction for this profile. |
| `model`, `reasoning_effort`, `service_tier`, `image_detail` | Model/request defaults; consult manifest for effective values. Job service tier comes from the caller/application default rather than automatically selecting the profile tier. |
| `max_output_tokens` | Positive integer default allowance; caller may override or omit the limit. |

Each field rule has `description` (string, default empty), `enum` (unique nonempty
string list or null), `vocabulary` (object or null), and `terms` (string mapping,
default empty). `enum` and `vocabulary` are mutually exclusive. A vocabulary
reference has string `path`, `value_column`, and `definition_column`; the path
is relative to the original profile. Unknown profile/rule/reference keys are
rejected. Preservation/normalization flags guide the model; the exporter does
not independently rewrite or verify the prose to enforce them.

`prompt.txt` contains the rendered initial template, field list, rules, vocabulary
definitions, and optional `<profile-stem>.notes.md` text when enabled. The original
template and profile-note files are not separately copied. Continuation uses
the installed continuation template and records successful attempt prompts.

`source_image.*` preserves source bytes and extension. Preparation copies bytes
when no conversion or resize is needed. Otherwise it resizes proportionally
with Lanczos (default longest side 2800 pixels), converts to RGB, flattens alpha
over white where handled, and re-encodes as JPEG for JPEG suffixes or PNG otherwise.
Thus `was_converted` can be true without a filename extension change; resized
WebP/GIF paths can contain PNG bytes. When rewriting a multi-frame image only
the first frame is used; a no-rewrite copy preserves original bytes. Decode
images to inspect them rather than assuming the suffix proves the encoding.

Segments are full-width, top-to-bottom crops of the **prepared** image, saved as
RGB PNGs named `segment_001.png`, etc. Crop stride is
`max(1, segment_height_px - segment_overlap_px)`; the last crop may be shorter.
No separate crop-coordinate sidecar is saved. The rough token estimate uses
`ceil(width/512) * ceil(height/512)` times 85 (`low`), 255 (`high`), or 140
(`auto`/fallback including `original`). This is an application heuristic only.

## Cache, recovery, and gold examples

### Local request cache

Repository/application-root `.cache/geo_map_exp_extractor/requests/<fingerprint>.json`
stores `raw_response` (object), `data` (validated extraction envelope), `usage`
(five nullable token counts), `incomplete_max_output_tokens` (boolean), and
`token_limit_warning` (string or null). Interrupted/incomplete results are not
written as reusable entries. Cache files are separate from the project and need
not travel with it. Deleting them removes reuse opportunities, not saved projects.
This local cache is distinct from API prompt caching measured by `cached_tokens`.
The ordinary nonrecoverable job path still saves successful fresh results to
cache when lookup is disabled; GUI sessions gate both lookup and storage with
`use_cache`. A forced rerun disables lookup, not necessarily storage.

### GUI review recovery snapshots

Locations: Windows `%LOCALAPPDATA%/GeoMapExpExtractor/recovery`; macOS
`~/Library/Application Support/GeoMapExpExtractor/recovery`; other systems
`$XDG_STATE_HOME/GeoMapExpExtractor/recovery` or
`~/.local/state/GeoMapExpExtractor/recovery`. Filename is
`<sha256-of-resolved-project-path>-<session-id>.json`.

| Snapshot key | Type/meaning |
|---|---|
| `version` | Integer `1`; unknown outer keys rejected. |
| `project_dir` | Absolute project path; recovery is tied to this location. |
| `run_id` | Project run identifier. |
| `request_fingerprint` | Project identity check. |
| `saved_at` | Timezone-aware timestamp. |
| `base_revision` | Hash of saved project state against which edits began. |
| `state` | Review state object described below. |

`state` contains `fields`, `rows`, `original_rows`, `row_statuses`, `row_comments`,
`feedback_records`, `notes_text`, `pending_targets` (zero-based row indices,
default empty), `pending_status` (default `needs_review`), and `pending_comment`
(default empty). Fields are unique strings; rows/baselines are string-valued
objects with exactly those fields. Rows, originals, statuses, and comments must
have matching lengths. Statuses use the three GUI row statuses; pending targets
must be in range. Feedback is a list of objects; notes/comment text is string.
Unknown state keys are rejected and strict type validation applies.

`base_revision` hashes the ordered labels and bytes of manifest, corrected JSON,
extracted JSON, notes, and feedback; a missing file contributes `<missing>`.
It detects changes on disk, not just time elapsed. Review-state digest uses
sorted-key, Unicode JSON and SHA-256 to detect dirty content. Recovery polls
every 5 seconds, saves after about 30 seconds idle or 120 seconds dirty, and
waits at least 30 seconds between failed-save retries. These are scheduling
targets, not guarantees against edits lost before a snapshot. Explicit saving
ends the current recovery session and starts a new baseline. Recovery snapshots
contain review content, not credentials, image bytes, or model settings.
See [recovery workflow](../README.md#automatic-recovery-copies).

### Gold examples

Promotion copies saved corrected outputs to
`examples/gold/<profile_id>/<run_id>.corrected.json` and `.corrected.csv` under
the application root. These are curated table copies, not complete run archives
or automatic model training. The GUI blocks promotion while continuation is
available. Preserve the original run folder for provenance.

## Troubleshooting and audit limits

1. **Missing rows or zero rows:** check status and warnings before blaming CSV
   import. Inspect raw output and the last attempt. Token exhaustion can occur
   before any complete row. Partial JSON recovery deliberately discards unfinished
   rows. A `complete` status still does not prove every source row was recognized.
2. **Missing corrected files:** they appear only after saving review or continuing.
   Existence alone does not mean accepted review; inspect `final_review` statuses.
3. **CSV edits disappear on reopen:** the GUI loads JSON. Review through the GUI
   and save; keep independently transformed CSVs as separate downstream products.
4. **Continuation rejects changed inputs:** restore the checkpoint-hashed files
   from an intact copy, or start a new extraction with changed inputs. Do not
   change hashes merely to suppress the check.
5. **Unexpected duplicates:** inspect crop overlap and continuation boundary
   warnings. Review joins against the source, including hierarchy and headings.
6. **Cost differs from a bill:** distinguish local cache reuse, API cached tokens,
   inherited continuation usage, pending usage, and local catalog estimates.
7. **Moved project has no recovery edits:** recovery is local and path-specific.
   Save Project before moving and copy the entire folder, not just the table.

The audit trail records useful evidence, not every execution detail. It does not
save API credentials, a full HTTP request log, every poll/retry, hidden reasoning,
a guaranteed immutable model revision, Git commit, dependency versions, pricing
snapshot, explicit original preprocessing limit, reviewer identity, or persistent
row IDs. Included prompts and outputs may contain source text and review notes;
sharing a run shares that content. Some derived metadata is rewritten on load.
Retain an untouched archive of important runs and parent continuations before
further review if a fixed historical record is needed. Repeating a request does
not guarantee identical model text.

basename to `.raw.json`, `.prompt.txt`, and `.manifest.json`; `build_manifest()`
uses `input_image_path`, `input_image_dimensions` (`width`, `height`),
`profile_path`, `profile_id`, `model`, `timestamp`, `output_file_paths`, and
`package_version`. Current GUI/CLI jobs use the run-folder manifest documented
above, not that helper format. Do not confuse `output_file_paths` with current
`output_paths` when writing readers for legacy files.
